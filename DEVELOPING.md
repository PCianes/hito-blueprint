# Developing the base

This repository is where the base is developed and published. It is also the template every copy starts from, so it is a copy with no notes: the content folders hold only their `README.md`, and `custom/` only its examples. Keep it that way; notes belong in a copy.

- **Set up once after cloning:** `sh blueprint/scripts/install.sh` and `git config hito.develop true`. Without that setting this repository is checked as a copy, which may not edit `blueprint/`; git never clones it, so no copy inherits it.
- **Here `blueprint/` is edited**, but only with what helps any copy. What is for one person goes in that person's `custom/`. After editing it, regenerate its fingerprint in the same commit: `sh blueprint/scripts/check.sh --manifest > blueprint/MANIFEST`. The check fails until you do, because the template gives new copies the main branch as it is.
- **Nothing personal enters this repository.** It is public, and with `hito.develop` the git hooks stop a commit that adds Spanish to Markdown, to a file name or to its message, a path into a home folder, or a personal email address. Tests and examples use made-up data.
- **Before saying a change to something that runs works** (`blueprint/scripts/`, `blueprint/git-hooks/`), try to break it: a test that fails for the reason it should, and each fault the check must stop put in on purpose. Then rehearse: `sh dev/rehearse.sh` uses hito as a person does, with real commits through the git hooks, a new copy from the template, an owner's mistakes, a clean clone and `update.sh` from the previous version, all in throwaway folders; `sh dev/rehearse.sh <copy>` also updates a throwaway clone of a real copy. The pipeline (`.github/workflows/check.yml`) runs the full check and the rehearsal on every push, on Linux and macOS, and also on Windows when launched by hand (`gh workflow run check.yml`), which takes about 40 minutes. A change to text only needs the check.
- **Commits are public.** Conventional Commits in English, with nothing personal in them, signed with an address that is not private.
- **A branch lives only while it is needed.** Once its work is in main, or is given up, delete it, here and on GitHub (`git push origin --delete <branch>`), in the same sitting: a version is kept by its tag, not by a branch.
- **To publish a version:** set `blueprint/VERSION` to it, add its section at the top of `blueprint/CHANGELOG.md` (mark **Breaking** what asks copies to do something), regenerate `blueprint/MANIFEST`, commit, push and wait for the pipeline to pass; launch it by hand for Windows (`gh workflow run check.yml`) and wait for that too; then tag it with the same name (`git tag v0.2`) and push the tag. `update.sh` refuses a tag whose `VERSION` says otherwise. The template gives new copies the main branch as it is, so only what passed the check goes there.
- **Contributions are not accepted**, so issues stay off.
