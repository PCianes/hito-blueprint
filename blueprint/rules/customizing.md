## Customizing

`blueprint/` is shared by every copy. Improvements that would help every copy are made in the base itself, where it is developed. Changes for one person never go in `blueprint/`; they go in `custom/`:

- a file in `custom/rules/` with the same name as a base rule replaces it (`custom/rules/links.md` replaces `blueprint/rules/links.md`);
- your own rules are files named `my-*.md` in `custom/rules/`;
- to leave a base rule out, add a line `rules/<name>` to `custom/disable`: the rule stays in `blueprint/`, untouched, but no longer reaches `AGENTS.md`, and updates cannot bring it back;
- rules that hold in every folder, not only in this repository, are files named `my-*.md` in `custom/global/rules/`, and such skills are folders named `my-*` in `custom/global/skills/`. They go in `GLOBAL.md`, which `blueprint/scripts/global.sh` takes to each agent outside the repository, and also at the end of `AGENTS.md`, so they hold here even where `global.sh` has not run. Whatever speaks of this repository (its folders, its commits) stays in `custom/rules/`.

Besides rules, `custom/skills/` holds the owner's skills (see Skills), `custom/git-hooks/commit-msg`, if present, is run with the commit message and can reject it, and `custom/git-hooks/test-*.sh` run with the other tests. Anything else in `custom/` makes the check fail. `AGENTS.md` and `GLOBAL.md` are generated by `blueprint/scripts/rules.sh`. Never edit them by hand.
